# Changelog — Batch 1: Source-of-truth consolidation (2026-05-03)

## Summary

- **What changed:** Added a canonical config capability registry (`docs/config-registry.json`) with generated docs and CI freshness guard; added Android root-level unknown-field preservation to prevent silent loss of advanced config; added Markdown heading-anchor validation for `file.md#anchor` links and wired it into CI; consolidated CI **repo-sanity** and local drift verification behind `tools/run-repo-sanity.py` (including extracted JSON/XML/Android-string/stale scan); documented **`nested_fields`** for `vercel`, `account_groups[]`, `domain_overrides[]`, and `fronting_groups[]` in the registry JSON with generated **Nested object schemas** in `docs/config-registry.md`; added **`tools/check-config-registry-nested-fields.py`** so those **`nested_fields`** key sets stay aligned with Rust struct fields (via **repo-sanity**); documented **`hosts`** via **`value_semantics`** plus **`tools/check-config-registry-map-semantics.py`** so map-typed roots carry prose semantics.
- **Why:** Prevent split-brain between Rust schema, Desktop/Android config I/O, example configs, and docs; ensure docs links (including Persian) don’t silently break as headings evolve.

## Remaining risk

- Registry models the **47 serialized `Config` keys** plus **`nested_fields`** metadata for **`vercel`**, **`account_groups[]`**, **`domain_overrides[]`**, and **`fronting_groups[]`** (generated tables in `docs/config-registry.md`; **`nested_fields`** keys mechanically checked vs Rust structs). **`hosts`** uses **`value_semantics`** plus a mechanical **`map<`** drift gate (not per-key **`nested_fields`**). Other shapes (readiness-only blobs, …) are not yet catalogued the same way.
- Android preservation is root-level only; nested preservation is still domain-specific (account groups already have their own preservation path).
- Backend rows in `docs/parity-matrix.json` are maintainer taxonomy, not mechanically derived from Rust; **`backend_taxonomy`** pins canonical IDs and matches `backends` key order (checker-enforced); only **mode** keys are cross-checked against `Mode::as_str`.
- `docs/platform-defaults.json` now covers several hot-path importer defaults; richer LAN/domain/runtime/auto-tuning fields are still not exhaustively enumerated there.
